# ADR-0004: Git project knowledge proposals, without automatic vault writes

- **Status:** Proposed (v0 pilot)
- **Date:** 2026-10-27
- **Extends:** [ADR-0003](ADR-003.md)

## Context

Maintaining the private Obsidian knowledge vault by manually transcribing each public
project's technical details would duplicate work. Source repositories already contain
project history, code, CI and documented tests. However, repository ownership and
mentions are **not** personal career achievements on their own.

## Decision

Implement an opt-in CLI `knowledge-propose --repo LOCAL_GIT_CLONE` that:

- reads **committed blobs at HEAD** from a local Git checkout, not untracked/dirty files;
- considers only tracked README files, `docs/evidence/*.md`, Terraform files,
  Docker/Compose descriptors, GitHub Actions workflows and `pyproject.toml`;
- scans a bounded number of UTF-8 files and filters obvious secret-bearing lines;
- produces a short Markdown **proposal** with source file, exact line number and commit;
- links to commit-pinned GitHub lines only if `origin` is a strictly validated GitHub URL;
- uses `career_evidence: false` and `status: proposed` so the Vault Reader ignores it;
- prints to stdout unless the user explicitly supplies `--output`; **never imports or
  changes the private vault**, and rejects output inside source repo or specified vault.

This is deliberately not AI-authored achievement text, a repository crawler with tokens,
or a direct GitHub API integration. The local clone is an existing GitHub repository,
read through Git, with no extra account connector required.

## Trade-offs

- Fast and reproducible without additional LLMs, vector indexes or remote permissions.
- Existing source files are evidence of **documented/committed work**, not proof of
  production deployments, authorship, skill level or correctness.
- Lexical matching misses some concepts and may select incidental mentions. It cannot
  automatically distinguish experimental emulators from real cloud, or infer impact.
- The user must still approve the note and verify whether each claim reflects their work.
- Only a conservative source allowlist is scanned. We can expand it when a real project
  demonstrates a need; larger private/archived/binary files are intentionally excluded.

## Exit criteria

Given a clone of `agent-platform-cloud-lab`, a generated note must cite the README,
committed infrastructure code and available Floci test evidence, retain the original
Git commit, and remain ignored by Job Review until explicitly approved in Obsidian.
