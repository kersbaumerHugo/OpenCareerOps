# ADR-0003: Markdown vault as the canonical knowledge source

- **Status:** Proposed (pilot implementation)
- **Date:** 2026-10-27
- **Updates:** [ADR-0002](ADR-002.md) (Git remains authoritative)

## Context

Maintaining a hand-scored `state/current.json` makes the user perform extra work before
OpenCareerOps becomes useful. Career information already appears naturally in project notes,
learning logs and evidence files. Obsidian edits Markdown locally; Git versions those files.

## Decision for the pilot

- Keep **public OpenCareerOps** as the engine and tests, with only fictional fixtures.
- Use a **separate private Git-backed Obsidian vault** for human knowledge: Markdown and optional
  YAML frontmatter. No mandatory template, action score, or task entry.
- Read only the top-level `Career/`, `Projects/`, `Evidence/` and `Learning/` folders.
  Exclude `00-Inbox/`, hidden paths, symlinks, unchecked/checked task items, planned sections,
  code fences and explicit `career_evidence: false` notes.
- Treat matches as **textual mentions**, never verified expertise. Retain source file and line;
  human review is mandatory before an achievement appears in a CV.
- Keep the **legacy JSON snapshot and weekly CLI** for backward compatibility, but do not
  require it for Job Review. Structured state can later be derived from approved vault notes.
- No automatic writes to the vault, Git, job applications, or task records during review.

## Consequences and boundaries

- A report can be generated from ordinary notes without maintaining a separate database.
- Markdown formatting and casual prose can create false matches; v0 deliberately reports
  *mentions*, not semantic understanding or proof.
- YAML parsing uses `yaml.safe_load`, not arbitrary code execution. Only narrative body lines
  count as evidence; metadata and file names never establish a skill match.
- Repositories containing personal notes **must be private**; Git history permanently retains
  earlier versions until actively purged. No tokens, passwords, or sensitive personal records.
- The Obsidian UI is optional at runtime: OpenCareerOps reads ordinary files from disk.

## Exit criteria

Demonstrate `opencareerops job-review --job vacancy.txt --vault ~/projects/personal-vault`
producing a deterministic report that cites `Projects/X.md:L12`, without any manual task entry.
Reassess the evidence selection policy before adding AI extraction or automated suggestions.
