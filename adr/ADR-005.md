# ADR-0005: Conservative evidence curation before vault approval

- **Status:** Proposed (v0 pilot)
- **Date:** 2026-10-27
- **Extends:** [ADR-0004](ADR-004.md)

## Context

The initial `knowledge-propose` output preserves Git provenance but emits a large,
low-signal list of isolated code lines and technology mentions. A personal knowledge
base requires concise, truthful records that reduce manual processing time.

## Decision

Add `knowledge-propose --curated` as an **opt-in**, deterministic presentation layer.
It groups source-backed observations into at most five candidate categories, retains
commit-pinned links and explicit limitations, and does not claim contribution,
production operation, experience level or impact on the author's behalf.

Keep the detailed output as the default, extend the bounded observations available to
curation, and continue to mark every generated note `career_evidence: false`.
The existing read-only Git/vault boundaries remain intact. No new LLM, database,
external service or task-management state is introduced.

## Trade-offs and follow-up

Heuristics may miss relevant work, group unrelated facts, or include an incidental
configuration reference. Documentation reports are not independent verification of
tests. The user's acceptance still requires reading and correcting each candidate.
If quality is insufficient after real use, improve the source contracts and test
corpus before considering a generative synthesis layer.
