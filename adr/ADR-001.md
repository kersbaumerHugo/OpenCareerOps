# ADR-0001: Notion as the Operational Source of Truth

- **Status:** Superseded by [ADR-0002](ADR-002.md) on 2026-10-14
- **Date:** 2026-07-24
- **Deciders:** Hugo Kersbaumer
- **Tags:** architecture, notion

## Context

O OpenCareerOps precisa manter informações dinâmicas como estado da carreira, próximos passos, histórico e prioridades.

Esses dados devem ser facilmente editáveis, visualizáveis e integráveis com automações.

Era necessário escolher uma fonte operacional única para evitar inconsistências e duplicação de informações.

## Decision

O Notion será adotado como a fonte operacional de verdade (Operational Source of Truth).

O GitHub permanecerá como a fonte técnica do projeto (código, documentação, arquitetura e automações).

O sistema lerá informações do Notion por meio da API oficial, sem duplicar os dados operacionais em outros locais.

## Consequences

### Positive

- Interface amigável para atualização manual.
- Banco de dados estruturado.
- API oficial.
- Fácil compartilhamento.
- Boa integração com IA.
- Evolução sem necessidade de desenvolver uma interface própria.

### Negative

- Dependência de serviço externo.
- Limitações da API.
- Requer autenticação.

### Risks

- Mudanças na API do Notion podem exigir adaptações futuras.

## Alternatives Considered

### GitHub Issues

Excelente para desenvolvimento.

Ruim para representar estados operacionais complexos.

### YAML Files

Muito simples.

Pouco amigável para edição manual.
### SQLite

Boa persistência.

Necessitaria criar interface de administração.

### Obsidian

Ótimo para conhecimento.

Fraco para modelagem relacional de estados e tarefas.
