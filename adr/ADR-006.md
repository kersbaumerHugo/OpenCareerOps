# ADR-0006: Opt-in evidence-grounded LLM writer

- **Status:** Proposed (v0 pilot)
- **Date:** 2026-10-28
- **Extends:** [ADR-0005](ADR-005.md)

## Context

The deterministic Knowledge Bootstrap and Evidence Curation already identify commit-pinned
source lines, tests and limitations. Their output remains awkward for a personal portfolio:
regexes can identify signals but cannot reliably turn them into clear professional prose.

## Decision

Introduce the optional `knowledge-propose --writer llm` path. Keep the old detailed
(default) and `--curated` deterministic flows unchanged.

1. Inspect committed files at Git HEAD with the existing bounded reader.
2. Construct a small, structured evidence packet from curated groups, recorded limits and
   environment context. Assign temporary `E###` IDs locally.
3. Send only that packet to a user-configured OpenAI-compatible Chat Completions endpoint.
   Loopback HTTP(S) is allowed; a remote endpoint requires **both HTTPS** and
   `--allow-remote-llm`. No request is made in deterministic mode. Never log API keys.
4. Require strict JSON with `claims` and `limitations`, each citing existing evidence IDs.
   Reject unknown/duplicate IDs, oversized/invalid outputs, first-person claims and
   obvious unsupported numbers or unverified production assertions.
5. Resolve source links locally to exact commit/file/line. Always render context and
   limitations from the original deterministic scan as well, even if the model omits them.
6. Write a proposed Markdown note **outside** the source repo and Obsidian vault, with
   `career_evidence: false`. Never approve, commit, create tasks or send applications.

## Boundaries

- A valid ID **does not prove** that a claim is semantically entailed. Human approval of
  attribution, actual execution, correctness and context is still required.
- Credentials are passed via `OPENCAREEROPS_LLM_API_KEY`, not CLI arguments or Git.
  An explicitly authorized remote call sends selected **source excerpts** outside the
  user's machine; do not use a remote provider with confidential work without permission.
- Untrusted repository lines are data, not instructions. The application does not run
  code from inspected repositories or use the model as a source of evidence.
- The parser fails closed on invalid model output; never silently fall back to a
  seemingly approved report. The deterministic `--curated` option remains available.
- The CI uses mocked provider responses and makes no live model calls.

## Revisit when

A real Cloud Lab draft reveals source/citation relevance issues, providers require
nonstandard APIs, or automated factual validation is supported by an explicit test set.
Add only the smallest contract changes supported by measured quality problems.
